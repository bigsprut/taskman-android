# PLAN — Ф1: список в полный рост

Ветка: `phase/1-list-full` (от свежего `main` после merge #7) · ТЗ §5.3-Ф1, §6, §4, §9-Ф1
· Вопросы/ответы предыдущей фазы: `QUESTIONS.md`, `ANSWERS.md`

## Цель и критерий приёмки (§9-Ф1)

Фильтры/счётчики/подзадачи/чекбокс/удаление свайпом — по §5.3-Ф1; **мутации долетают до
сервера**; тест-записи с префиксом `__ТЕСТ` создаются и вычищаются в одном прогоне.

Продуктовые ограничения (проверяются на ревью):
- в списке **нет кнопок удаления** — только смахивание;
- у групп чипов-фильтров — **читаемые подписи**;
- цветной текст на залитом фоне — **авто-контраст по яркости**;
- **сортировка ≠ фильтр**: порядок `STATUS_ORDER` остаётся, фильтр только отбирает строки.

## Что берём из Ф0 без переделки

`TaskRepository` (мьютекс синхронизации, исходы 401/403/409/4xx, валидация `server_time`),
Room-снапшот и `StateMapper`, `StatusOrder`, M3-каркас и тему, `TaskListViewModel`,
`ApiFailure` (в т.ч. `Conflict(actualUpdatedAt)`), мок-сервер (расширяем мутациями).

## Решения фазы (и почему так)

1. **Чекбокс — через `POST /api/tasks` (UPSERT полного объекта) с `updated_at` (CAS).**
   ТЗ §4 обязывает клиент слать `updated_at` при каждом upsert и обрабатывать 409; отдельного
   CAS у `/toggle` в контракте нет. Payload собирается **из полной Room-сущности**, а не из
   строки UI: сервер перезаписывает всё, что не передано, дефолтами.
   `status_date` не отправляем (§4: без необходимости сдвигает даты). `completed_at` оставляем
   `null` — по эталонной фикстуре сервер проставляет его сам при смене статуса
   (`completed_at` = ts последней записи истории).
2. **Фильтр отбирает только родителей; дети показываются всегда.** `▸ N/M` считает всех
   детей (прогресс родителя). Изначально планировалось фильтровать и детей, но живая
   проверка показала тупик: у группы `▸ 3/3` все дети выполнены, и под фильтром «Активные»
   раскрытие вело в пустоту. Ребёнок живёт в контексте родителя — так и оставили.
3. **Один источник правды для мутаций — сервер.** После успешной мутации делаем `refresh()`,
   локальную копию руками не патчим: так не расходимся с историей/датами, которые считает сервер.
4. **409 не «лечим» перезаписью.** Показываем явное сообщение, обновляем состояние с сервера,
   пользователь повторяет действие сам (§4: «не перезаписывать молча»).
5. **Офлайн-очереди в Ф1 нет** (это Ф4): сетевой сбой = сообщение с точной причиной, без
   оптимистичного «успеха».

## Риски

| Риск | Страховка |
|---|---|
| UPSERT затирает поля, которых клиент не знает | payload только из полной сущности; тест полноты |
| Сервер не проставляет `completed_at` при UPSERT | проверка на моке + вопрос мейнтейнеру в отчёте; при подтверждении — отправлять `status_date` |
| Гонка с PWA-клиентом | CAS `updated_at` → 409 → явное сообщение + `refresh()` |
| Свайп конфликтует со скроллом | горизонтальный `SwipeToDismissBox`, подтверждение диалогом |
| Подзадачи-сироты (родитель удалён/скрыт) | в группы не попадают, считаются отдельно в отчёте |

## Definition of Done

1. `clean test assembleDebug lintDebug` — зелёный, lint без замечаний.
2. На моке: чекбокс меняет статус на сервере, смахивание удаляет задачу и поддерево,
   фильтры/счётчики/группы работают, 409 показывается явно.
3. Сценарий `__ТЕСТ`: создать → выполнить → удалить в одном прогоне, следов не остаётся.
4. `PHASE-REPORT.md` + PR в `main`; живая приёмка — Алина на устройстве.
