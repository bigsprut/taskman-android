## 2. Решения фазы

1. **Ссылка на файл собирается в одном чистом объекте** (`AttachmentUrls`): base + путь + токен.
   Это единственное место, где токен попадает в URL, — легко тестируется, и его нельзя
   случайно залогировать (HTTP-логирование в приложении выключено).
2. **Два сетевых клиента.** API-клиент добавляет `Token`/`X-Device-Id` заголовками;
   клиент файлов — **без** интерсептора: у `/api/attachments/{id}` токен только в query,
   ссылка абсолютная, а интерсептор подменил бы хост/путь и добавил лишний заголовок (§4).
3. **Coil 3 работает через тот же файловый клиент** (`SingletonImageLoader.Factory` в
   `TaskmanApp`) — кэш общий, отдельного сетевого стека нет.
4. **FileProvider + приватный кэш.** Наружу отдаётся `content://` с временным правом чтения;
   имя файла санитизируется (`safeAttachmentFileName`), чтобы `../` из чужого имени не вывел
   запись за пределы каталога.
5. **«Поделиться» переживает пересоздание Activity**: очередь uri живёт в `ShareInbox`
   контейнера, UI показывает выбор задачи из текущего фильтра.
6. **Сотрудники — отдельный репозиторий** с тем же паттерном, что и мутации задач:
   успех → `refresh()` (имена в задачах хранятся строкой, переименование видно только из
   свежего снапшота).

не прочитался — сообщение об ошибке показано корректно. Сам аплоад того же файла через
выбор файла проверен и доходит до сервера.

## 4. Раздел «server» (ТЗ §7)

Сервер не менялся; расхождений контракта, ломающих Ф3, нет. Наблюдения:

1. **`updated_at` задачи при аплоаде вложения.** На моке версия задачи не меняется; если живой
   сервер поднимает `updated_at` при добавлении вложения, это влияет на CAS при сохранении
   редактора (клиент после успеха делает `refresh()`, поэтому CAS-версия подтянется — но
   проверка на живом сервере полезна). Вопрос Q14.
2. **Идемпотентность `DELETE`** — см. Ф2 Q8: повторный DELETE даёт 404, для Ф4 хотели бы 200.
3. **Размер вложений.** Клиент читает выбранный файл целиком в память (для типичных фото/PDF
   приемлемо). Если на сервере есть лимит меньше клиентского, полезно отдавать его в `/api/state`
   или в ошибке `413` — сейчас клиент покажет «Сервер ответил ошибкой 413».

## 5. Ограничения Ф3

- Вложения из фикстуры на моке отдаются заглушкой объявленного размера (самих байт в фикстуре нет).
- Нет полноэкранного просмотра картинок внутри приложения: превью в строке + открытие внешним
  приложением (по §5.3-Ф3 этого достаточно).
- Сотрудник в задаче по-прежнему хранится именем строкой (переименование в справочнике не
  переписывает исторические задачи) — это ограничение контракта, рекомендация в Ф2 §4.
- Офлайн-очередь (Ф4): при сетевом сбое аплоад/удаление показывают сообщение, повтор — вручную.
