# PLAN — Ф6: UX-фиксы по живой приёмке

Ветка: `phase/6-ux-fixes` (от `main` после merge Ф5) · Основание: замечания живой приёмки
Ф0–Ф5 на OnePlus 15 и обновлённый `TZ-01-android-app.md` §5.3-Ф2 (решение владельца 20.11)

## Что чиним

1. **Создание задачи из списка** (дыра ТЗ, теперь в §5.3-Ф2): в списке не было средства
   создания — только чтение. Добавляем FAB «+» с быстрым диалогом (название), остальное —
   дефолты сервера: категория по умолчанию из настроек, статус «Создана», первый список.
2. **Выбор сотрудника** (фича владельца): чипы-кнопки заменяем на **лист-список с поиском** —
   справочник может быть большим. Отдельный пункт «Без сотрудника», отметка выбранного.
3. **Ошибки входа** (§4): 401 (неверный токен) и сетевая ошибка должны показываться разными
   сообщениями. Маппинг вынесен в тестируемую функцию, защитная ветка для `Http(401)`,
   тексты явные.

## Решения

1. **Создание — FAB + диалог, а не полноценный редактор новой задачи.** ТЗ допускает
   «FAB «+» или поле сверху»; быстрый ввод названия закрывает потребность, а полный редактор
   для новой задачи потребовал бы черновика без id (id выдаёт сервер).
2. **Создание не буферизуется офлайн** (как подзадачи в Ф4): id выдаёт сервер, локально его
   не придумать; при сетевом сбое — сообщение. Решение зафиксировано в отчёте.
3. **Список сотрудников — `ModalBottomSheet` внутри листа редактора** с полем поиска,
   прокруткой и отдельным «Без сотрудника». Поиск — отдельная чистая функция
   (`filterEmployees`), проверяется JVM-тестом.
4. **Маппинг ошибок входа — отдельная функция** `ApiFailure.toLoginError()`: 401 → «неверный
   токен», `IOException` → «нет связи», `Http(401)` защитно → тоже «неверный токен».
   Это позволяет закрепить различие тестами без DataStore/Keystore.

## Риски

| Риск | Страховка |
|---|---|
| FAB перекрывает список/подзадачи | FAB только на вкладке «Список», в пределах Scaffold |
| Вложенный bottom-sheet конфликтует с листом редактора | отдельный `ModalBottomSheet` как sibling, закрытие — своим `onDismissRequest`; проверено живьём |
| Создание без списка в снапшоте | `firstListId()` вернёт `null` → понятная внутренняя ошибка, без запроса |
| 401 снова «превратится» в сетевую ошибку | отдельная функция маппинга + тест «401 ≠ сеть» |

## Definition of Done

1. `clean test assembleDebug lintDebug` зелёный, lint без замечаний.
2. Живьём: FAB создаёт задачу (сервер получает `id=null` и категорию по умолчанию);
   выбор сотрудника открывает лист с поиском, найденный сотрудник сохраняется в задаче;
   неверный токен даёт сообщение про токен, недоступный сервер — про связь.
3. `PHASE-REPORT.md` + PR.
