## 2. Решения фазы

1. **Создание — FAB + быстрый диалог, а не полноценный редактор новой задачи.** ТЗ допускает
   «FAB «+» или поле сверху»; быстрый ввод названия закрывает потребность, а редактор новой
   задачи потребовал бы черновика без id (id выдаёт сервер). Остальные поля новой задачи —
   дефолты сервера: категория по умолчанию из настроек (§4), статус «Создана», первый список.
2. **Создание не буферизуется офлайн.** Как подзадачи в Ф4: `id` выдаёт сервер, локально его
   не придумать; при сетевом сбое — сообщение, очередь не растёт. Вопрос Q22.
3. **Сотрудник — вложенный `ModalBottomSheet`** (sibling листа редактора), а не dropdown:
   большой справочник требует поиска и прокрутки. Фильтр — чистая функция `filterEmployees`,
   покрыта тестами. Выбор сохраняется именем (так хранит контракт `source`).
4. **Маппинг ошибок входа — отдельная функция** `ApiFailure.toLoginError()`: 401 (и защитно
   `Http(401)`) → «неверный токен», `IOException` → «нет связи», остальное — код/неожиданный
   ответ. Это и есть исправление: раньше текст ошибки было невозможно проверить без
   DataStore/Keystore, теперь таблица закреплена 10 тестами, включая регресс «401 ≠ сеть».

## 4. Ограничения и мелочи

- **Дубли имён сотрудников** выбираются неразличимо: контракт хранит в задаче имя строкой
  (`source`), поэтому два «Ивана» в справочнике для клиента — одно значение. Вопрос Q23.
- Быстрое создание задаёт только название; остальные поля — через редактор (две операции).
- Системный диалог выбора даты статуса — на английском: это системный `DatePickerDialog`,
  локализация зависит от устройства, а не от приложения.
