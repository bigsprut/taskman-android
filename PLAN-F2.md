# PLAN — Ф2: редактор задачи

Ветка: `phase/2-task-editor` (от `main` после merge Ф1) · ТЗ §5.3-Ф2, §4, §6, §9-Ф2
· Ответы приёмки Ф1: `ANSWERS-F1.md`

## Цель и критерий приёмки (§9-Ф2)

Редактор задачи в bottom-sheet: все поля; markdown-описание (ввод plain, просмотр
отрендеренным); статус + дата статуса задним числом + «История»; категория; теги; сотрудник;
дата создания; подзадачи (добавить, переименовать инлайн, галка, удалить). **Закрытие листа
любым путём = автосохранение.** Правка сохраняется и переживает переоткрытие листа и
убивание процесса. Обязательный регресс: несохранённые поля не теряются при действии с
подзадачей при открытом редакторе.

## Решения фазы

1. **Markdown: разбор — `org.jetbrains:markdown` (Apache-2.0), отрисовка — свой Compose M3.**
   Почему не готовая Compose-обёртка: популярные варианты (`mikepenz`-renderer, Markwon) тянут
   либо Kotlin-stdlib 2.4-метаданные (риск под built-in Kotlin 2.3.21 / AGP 9), либо View-интероп.
   Парсер JetBrains даёт корректный GFM без Android-зависимостей, а рендер в Compose M3 —
   контроль типографики по §5.2 и отсутствие `AndroidView`.
2. **Черновик — отдельная модель `TaskDraft`, живёт в ViewModel и не перезаписывается
   `refresh()`.** Это и есть механизм регресса: пока лист открыт, подзадачи меняются на
   сервере, а черновик родителя остаётся как его правил пользователь.
3. **Черновик сериализуется в `SavedStateHandle` на каждое изменение** — переживает поворот и
   убивание процесса; после восстановления помечается «есть несохранённое» и сохраняется при
   закрытии.
4. **Автосохранение при закрытии:** жест/внешний тап/back/кнопка — всё через `close()`.
   При сетевой ошибке или 409 лист остаётся открытым с сообщением: молча терять правки нельзя.
5. **Подзадачи** — отдельные мутации сразу на сервер (UPSERT с `parent_id` / DELETE), черновик
   родителя не трогают. `list_id` берётся из локальной записи родителя.

## Риски

| Риск | Страховка |
|---|---|
| Правки теряются при фоновом `refresh()` | черновик не из локальной модели списка, а из `TaskDraft` в VM |
| Процесс убит при открытом листе | JSON черновика в `SavedStateHandle` на каждое изменение |
| Автосохранение затирает чужую правку | CAS `updated_at`; 409 → сообщение, лист остаётся открытым |
| Подзадача привязана к неверному списку | `list_id` берётся из записи родителя, а не из UI |
| Markdown-рендер ломает раскладку | отдельный модуль `ui/markdown`, стили только из M3 |

## Definition of Done

1. `clean test assembleDebug lintDebug` зелёный, lint без замечаний.
2. На моке: открыть задачу → правка названия/описания/статуса/даты/тегов/сотрудника →
   закрыть любым путём → значение на сервере; подзадачи добавляются/переименовываются/удаляются.
3. Регресс-тест «подзадача не затирает черновик» есть и зелёный.
4. `PHASE-REPORT.md` + PR; живая приёмка — Алина на устройстве.
