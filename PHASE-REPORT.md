# PHASE-REPORT — Ф8: свайп-удаление везде

Ветка: `phase/8-swipe-everywhere` (от `main`) · Основание: `TZ-01-android-app.md` §5.2
(«удаление — M3 SwipeToDismissBox, смахивание влево, с подтверждением диалогом — ВЕЗДЕ»;
политика владельца: никаких видимых кнопок удаления, как в PWA taskman и ДиетолАге)

Итог: в редакторе задачи подзадачи и вложения удаляются свайпом влево с подтверждением;
видимых кнопок удаления в редакторе больше нет. Список задач и редактор используют один
общий компонент свайпа.

## 1. Что сделано

| Блок | Результат | Ключевые файлы |
|---|---|---|
| Общий свайп | `SwipeToDeleteRow` (влево, диалог подтверждения) + общий `DeleteSwipeBackground`; список задач переведён на общий фон | `ui/common/SwipeToDelete.kt`, `ui/list/TaskRow.kt` |
| Подзадачи | свайп по строке → «Удалить подзадачу?» → удаление; кнопка-корзина убрана | `ui/editor/TaskEditorSheet.kt` |
| Вложения | свайп по строке → «Удалить вложение?» → удаление с сервера; кнопка-корзина убрана | `ui/editor/TaskEditorSheet.kt` |
| Непрозрачный контент | фон свайпа больше не просвечивает в обычном состоянии строки (иначе «встроенные» корзины) | `ui/common/SwipeToDelete.kt` |
| UI-тесты | **3** instrumented: свайп-удаление подзадачи, отмена в диалоге, свайп-удаление вложения; корзин нет | `androidTest/.../EditorSwipeDeleteTest.kt` |

## 2. Решения

1. **Один компонент на всё приложение.** Список задач уже умел свайп; фон вынесен в общий
   `DeleteSwipeBackground`, а для редактора добавлен `SwipeToDeleteRow` с диалогом.
2. **Свайп не удаляет сразу.** Строка возвращается на место (`dismissState.reset()`), решение
   принимает диалог — как в списке и как требует ТЗ («с подтверждением диалогом»).
3. **Непрозрачный фон строки — обязателен.** Первая живая проверка показала «встроенные»
   корзины: `SwipeToDismissBox` рисует `backgroundContent` под контентом, и при прозрачной
   строке красный фон с иконкой был виден всегда. Обёртка `Surface(surfaceContainerLow)`
   внутри `SwipeToDeleteRow` закрывает дефект.
4. **Порог свайпа — треть ширины**, чтобы случайный короткий жест не открывал диалог.
5. **Пути удаления не менялись**: подзадача — через очередь мутаций (офлайн-очередь Ф4),
   вложение — прямым `DELETE` с рефетчем; убраны только кнопки.
6. **Тестовый тег `EditorTestTags.CONTENT`** на списке полей редактора — для стабильной
   прокрутки в UI-тесте (поиск по признаку «есть вложенный TITLE» ловил узел, который Compose
   пересоздаёт при первой компоновке).

## 4. Замечания и ограничения

1. **Два устройства в adb.** Во время проверки к `adb` был подключён физический телефон
   (приёмочное устройство) — все команды выполнялись явно с `-s emulator-5554`, установка и
   тесты на телефон не шли. В инструкции для будущих агентов это стоит помнить.
2. **Имена instrumented-тестов без пробелов.** D8 (minSdk 26, dex < 040) не принимает пробелы
   в именах методов: backtick-имена с пробелами роняют `assembleDebugAndroidTest`
   («Space characters in SimpleName ... are not allowed prior to DEX version 040»).
   В androidTest имена — с подчёркиваниями.
3. Свайп по строке подзадачи делается по текстовому полю (переименование) — жест проходит,
   что подтверждено и UI-тестом, и живьём.
4. Настройки/справочники (теги, категории, сотрудники) по-прежнему удаляются кнопками: политика
   «только свайп» касается удаления задач/подзадач/вложений; для CRUD справочников свайп
   не просили.
