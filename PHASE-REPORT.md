## 2. Решения фазы

1. **Порядок сортировки — на устройстве.** Контракт `PATCH /api/settings` знает только
   категорию по умолчанию; порядок — вкус пользователя конкретного устройства, поэтому
   DataStore, а не снапшот. Подзадачи всегда сортируются `STATUS_ORDER` — иначе теряется смысл
   `▸ N/M`.
2. **Категория по умолчанию отправляется с явным `null`.** «Снять категорию» — это
   `{"default_category": null}`, а kotlinx.serialization с `explicitNulls = false` выбросил бы
   поле из DTO и отправил `{}`; сервер мог бы понять это как «не менять». Поэтому тело
   `PATCH /api/settings` — `JsonObject`, собранный вручную. Вопрос Q20.
3. **Цвета нормализуются в VM, репозиторий отправляет как есть.** Невалидный ввод не уходит
   на сервер: диалог показывает подсказку «Формат: #rrggbb», а пустой цвет заменяется
   `#4a5c92`.
4. **Экспорт — чистая функция над снапшотом Room.** Строки статусов и форматирование даты
   приходят снаружи (из UI), поэтому формат проверяется JVM-тестами и не тянет Android-ресурсы.
   Категории без задач не выводятся: экспорт — список задач, а не каталог. Вопрос Q21.
5. **Кнопка «Отправить сейчас» отправляет сразу**, а не только ставит работу в WorkManager:
   уникальная работа с `KEEP` может ждать предыдущую с backoff, и кнопка выглядела бы
   «мёртвой» (это и обнаружилось на живой проверке — исправлено). Планировщик всё равно
   дёргается как страховка.
6. **Стриминг-аплоад** закрывает техдолг Q16: файл не читается в память целиком,
   `Content-Length` из `OpenableColumns.SIZE`, при неизвестном размере — chunked.

## 6. Server (§7)

Сервер не менялся. Наблюдения по контракту:

1. `PATCH /api/settings` — единственное место, где «нет значения» и «значение null» различаются;
   клиент теперь отправляет явный `null` (см. §2.2). Нужно подтверждение поведения сервера (Q20).
2. `DELETE /api/tags/{id}` — сервер должен чистить ссылки в задачах (мок чистит); если живой
   сервер оставит висячую ссылку, клиент покажет пустое место в бейджах — это багрепорт.
3. Идемпотентный `DELETE` (Ф2 Q8) по-прежнему был бы полезен для ретраев очереди.
