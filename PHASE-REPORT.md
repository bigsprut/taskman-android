числом» с историей, подзадачи (добавить/переименовать/галкой/удалить). Закрытие листа любым

## 2. Решения фазы (обоснования)

1. **Markdown: парсер — библиотека, рендер — свой (требование §5.3-Ф2 «библиотеку
   обосновать»).**
   *Почему так:* разбор отдан `org.jetbrains:markdown:0.7.18` (Apache-2.0, GFM,
   `kotlin-stdlib 2.0.0` — совместим с нашим Kotlin 2.3.21), а отрисовка — собственный
   Compose M3-компонент. Готовые Compose-обёртки (`mikepenz:multiplatform-markdown-renderer`,
   Markwon) пришлось бы либо тянуть с Kotlin-stdlib 2.4-метаданными (риск под built-in
   Kotlin/AGP 9), либо подключать через `AndroidView`. Свой рендер — это ~200 строк на
   `AnnotatedString`, зато стили строго из `MaterialTheme.typography` (§5.2), кликабельные
   ссылки через `LinkAnnotation.Url`, никакого View-интеропа и ноль лишних зависимостей.
   Поддержано: параграфы, заголовки 1–6, маркированные/нумерованные списки, цитаты, блоки
   кода, горизонтальная линия, bold/italic/strike/inline-code/ссылки/автолинки.
   Не поддержано осознанно: таблицы, HTML, картинки (alt-текстом), вложенность списков
   (схлопывается в один уровень — модель по ТЗ глубины не несёт).
2. **Черновик — отдельная модель `TaskDraft`, не «строка списка».** Пока лист открыт, фоновый
   `refresh()` обновляет базу, но не черновик: это и есть механизм регресса §9-Ф2.
3. **Черновик в `SavedStateHandle` (JSON) на каждое изменение** — переживает поворот и
   убивание процесса; после восстановления помечается «есть несохранённое».
4. **Автосохранение при закрытии любым путём** (жест/внешний тап/back/кнопка) — один путь
   `close()`. При ошибке сети или 409 лист **остаётся открытым** с сообщением: молча терять
   правки нельзя.
5. **Подзадачи — отдельные мутации сразу на сервер** (`addSubtask`/`renameSubtask`/`toggle`/
   `delete`), `list_id` берётся из локальной записи родителя; черновик родителя не трогают.
6. **Дата статуса не сбрасывается при смене статуса** — выбранную дату сохраняем (порядок
   «сначала дата, потом статус» — обычная правка задним числом).

## 4. Раздел «server» (ТЗ §7)

Сервер не менялся. Наблюдение по итогам живой проверки:

1. **`status_date` и `completed_at` расходятся.** При правке «задним числом» клиент передаёт
   `status_date` (дата уходит в историю — проверено), но `completed_at` сервер ставит
   текущим моментом. В списке сортировка идёт по истории, поэтому пользователь этого не
   видит, но в PWA и в отчётах дата завершения будет «сегодня», а не выбранная.
   *Рекомендация:* при смене статуса с явным `status_date` ставить `completed_at = status_date`
   (если статус `completed`). Если сервер этого не хочет — клиент может слать `completed_at`
   сам (одна строка в `TaskPayload.fromDraft`), скажи, включим.
2. **Создание задач.** `POST /api/tasks` с `id: null` работает (подзадачи создаются так же),
   но в UI Ф2 нет кнопки «новая задача» — §5.3-Ф2 требует только редактор существующих и
   подзадачи. Вопрос Q11 ниже.

## 5. Ограничения Ф2

- Нет создания задачи верхнего уровня из UI (только подзадачи) — см. Q11.
- Вложения (Ф3) и CRUD справочников (Ф3/Ф5); поля «сотрудник»/«категория»/«теги» только
  выбираются из существующих справочников.
- Офлайн-очередь (Ф4): при ошибке сохранения лист остаётся открытым с сообщением, повторить
  можно нажатием «Готово»; черновик при этом сохранён локально.
- Markdown: вложенные списки схлопнуты, таблицы/HTML/картинки — текстом (см. §2.1).
