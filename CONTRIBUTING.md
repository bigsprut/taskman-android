# CONTRIBUTING

Спасибо за интерес! Проект — продакшн-клиент self-hosted таск-менеджера,
не демо: принимаются правки прод-уровня.

## Как внести вклад

1. Форкни репо (или используй ветку `phase/N-<slug>` по договорённости).
2. Прочитай **TZ-01-android-app.md** — полное ТЗ: контракт API (§6),
   стандарты (§5), запреты (§7), фазы (§5.3, §9).
3. Ветка: `feature/<краткое-имя>` или `phase/N-<slug>`.
4. Изменения кода — с тестами; сборка и тесты зелёные локально:
   `./gradlew test assembleDebug`.
5. PR в `main`: описание изменений по файлам, версии новых зависимостей,
   результат тестов (число тестов из `app/build/test-results`).
6. К каждому PR — файл `PHASE-REPORT.md` в корне ветки: что сделано,
   что проверено, что осталось.

## Правила

- **main защищён**: мерж только через PR с ревью мейнтейнера.
- **Секреты — никогда** в коде/коммитах/логах. base URL — из
  `local.properties` (gitignored), токен — вводится в приложении.
- Фикстуры `fixtures/` не менять: тесты не «зеленеют» подгонкой эталона.
- Новые зависимости — с обоснованием в PR (проект на бюджете $0,
  платных SDK не используем).
- Не добавлять: аналитику, краш-репортеры, рекламу.
- Серверный API не в зоне PR этого репо: расхождения контракта с фактическим
  поведением — issue с воспроизведением (метод/путь/тела/код ответа).
- Стандарт продукта: «личное приложение / один пользователь — и так сойдёт»
  — не аргумент. Отступления от стандартов Android/безопасности — только
  через issue с явным одобрением.
- Вопросы — GitHub issues.
