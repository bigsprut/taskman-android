## Контракты Ф6 (для продолжения работы)

- `TaskPayload.newTask(listId, title)` — `id=null`, `categoryId=null`, `status=created`.
- `TaskSnapshotReader.firstListId()` — список для новых задач (позиция 0), `null` = создать нельзя.
- `TaskMutationRepository.createTask(title)` — прямой путь, без офлайн-очереди.
- `filterEmployees(names, query)` — регистронезависимый поиск для листа сотрудников.
- `ApiFailure.toLoginError()` — единая таблица ошибок экрана входа.

## Правила, добытые в Ф6

1. **Новую задачу создаём через `id=null` + `category_id=null`** — категорию по умолчанию
   подставит сервер (§4), клиенту не нужно её резолвить.
2. **Создание не ставим в офлайн-очередь**: у записи нет id, сопоставление после ответа —
   отдельная фича (Q22).
3. **Список сотрудников — вложенный `ModalBottomSheet`** (sibling листа редактора), поиск
   сверху, «Без сотрудника» первым, выбранный отмечен галочкой.
4. **Ошибки входа должны различаться классами, а не текстом**: 401 → `LoginError.Unauthorized`,
   `IOException` → `LoginError.Network`; защитная ветка для `Http(401)` — обязательно.
5. **Маппинг/фильтры выносить в чистые функции** — их можно проверить JVM-тестом без
   DataStore/Keystore/Compose.
