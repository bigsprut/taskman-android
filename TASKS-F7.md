## Контракты Ф7 (для продолжения работы)

- `LocalTaskWriter.applyServerVersion(taskId, updatedAt)` — дефолт no-op для тестовых писателей,
  боевой пишет `UPDATE tasks SET updatedAt` в Room.
- `TaskMutationRepository.latestVersion(taskId)` — сначала подтверждённая сервером версия,
  затем снапшот; используется черновиком редактора после сохранения.
- `flush()`: 409 с версией из `acknowledgedVersions` → refresh + один повтор; иначе `Conflict`.
- `EditorUiState.conflict` + `reloadAfterConflict()` + баннер в `TaskEditorSheet`.

## Правила, добытые в Ф7

1. **Любой успешный upsert обязан применить `saved[].updated_at` локально** — иначе следующая
   мутация уйдёт со старой версией и получит ложный 409 «сам с собой».
2. **Свой конфликт отличаем по карте подтверждённых версий**, а не по снапшоту: снапшот может
   отставать; сравнивать с допуском (float unix-время).
3. **Один тихий повтор**, не больше: второй 409 — реальный конфликт.
4. **Сообщение о конфликте внутри модального листа не видно через снекбар** (SnackbarHost под
   `ModalBottomSheet`) — рисуем баннер в самом листе с действием.
5. **No-op автосейв**: сравнивать поля/теги/`status_date` с локальной записью; `updated_at`
   и пустую `status_date` изменениями не считать.
6. **Ручная проверка через PowerShell/curl портит точность double** (`1793739031.36348` вместо
   `1793739031.3634815`) → CAS падает с 409. Для внешних изменений брать сырые числа через
   `System.Text.Json ... GetRawText()`. В приложении kotlinx.serialization сохраняет double точно.
